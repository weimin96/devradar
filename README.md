# DevRadar

**Mac 菜单栏里的开发活动雷达。**

DevRadar 用一个很小的菜单栏窗口，帮你快速看清电脑上正在运行的开发服务、占用的端口、所属项目，以及各个应用的网络上传/下载情况。

它适合经常同时运行 Node.js、Java、Python、Docker、IDE、AI 编程工具和本地代理的 Mac 用户。你不需要记命令，也不用打开活动监视器和终端来回查进程。

## 你可以用它做什么

### 管理本地项目

菜单栏底部的「项目」页可以保存项目目录，即使项目没有运行也能找到它。支持搜索、打开 Finder / 终端，以及在独立窗口编辑项目名称、目录和多个启动任务。项目列表直接展示全部启动任务，每条命令可独立启动、停止和查看日志，无需展开项目。

- 启动命令通过 `/bin/zsh -lc` 在项目内的指定相对目录执行，不会自动安装依赖。登录 Shell 的环境与交互终端可能不同；使用 nvm 等工具时，需在命令或登录配置中显式初始化环境。
- 任务提供运行状态、独立日志窗口和停止操作；日志仅在内存中保留最近 128 KB。收起菜单栏或关闭日志窗口不会停止任务，退出 App 时会确认并停止仍在运行的任务。
- 托管任务应保持前台运行。任务退出时会清理同一进程组内的子进程，不支持自行脱离进程组的守护进程或通过 `docker compose up -d` 管理容器生命周期。扫描到的监听端口作为独立信息展示，不代表服务已通过就绪检查。
- 展开项目后可读取 Git 分支、文件改动和相对上游的提交数量；数量基于本地跟踪信息，点击「获取远端更新」才访问远端刷新。
- 「拉取」仅允许干净工作区的快进更新，不会自动暂存、合并或变基；「推送」只推送当前分支的已有提交，不会自动提交文件或强制覆盖远端。执行前展示并重新校验目标远端和分支。
- Git 同步需要已配置上游分支。复用本机 Git credential helper 和非交互 SSH 认证；缺少认证、未配置上游、多地址或镜像推送配置需在项目终端中处理。一次执行一个 Git 操作，支持取消和超时结束。

项目配置保存在 `~/Library/Application Support/DevRadar/projects.json`。移除项目只删除应用内配置，不删除项目文件。配置读取失败时会保留原文件并禁止覆盖，可修复文件后重新读取。

### 看清正在运行的开发服务

DevRadar 会自动发现本机正在监听端口的开发进程，并尽量识别：

- 项目名称和项目目录
- 监听端口和 PID
- Node.js、Vite、Next.js、Java、Spring Boot、Python 等运行环境
- Docker / Docker Compose 服务
- CPU、内存和运行时长

多个端口属于同一个项目时，会自动归到一起，不再是一长串难以辨认的进程。

端口分组右上角的「收藏到项目」可预填项目目录和可复用的启动任务，确认后保存到「项目」。收藏会读取同仓库的全部已识别服务，不受端口搜索条件影响；不同进程的可复用命令分别生成任务，同一进程的多个端口只生成一个任务，已收藏目录会复用原有项目。启动任务按当前进程参数预填，不复制环境变量；IDE 启动的 Java、临时参数文件和 Docker 服务不会自动生成任务。

### 快速处理占用端口的进程

在菜单栏里可以直接：

- 打开本地服务地址
- 在 Finder 中打开项目目录
- 在终端中进入项目目录
- 停止或强制结束开发进程

### 查看哪些应用正在联网

切换到「网络监控」后，可以查看每个应用的上传和下载流量，包括：

- 实时上传 / 下载速度
- 1 天、3 天、7 天累计流量
- 按上传量或下载量排序
- 当前连接的远程地址
- Node.js、Python 等命令行进程对应的项目
- 尽量识别进程是由 Terminal、iTerm2、ChatGPT 等哪个应用启动的

对于长期运行、父进程已经退出的后台进程，macOS 本身可能已经丢失最初的启动关系。DevRadar 会继续根据工作目录、命令行和项目文件进行推断，因此这类归因属于尽力识别，并不保证 100% 准确。

## 安装

1. 从 GitHub 的 **Releases** 页面下载最新的 `DevRadar.app` 压缩包。
2. 解压后把 `DevRadar.app` 拖到「应用程序」。
3. 启动 DevRadar。
4. 顶部菜单栏出现网络图标后即可使用。

下载地址：<https://github.com/weimin96/devradar/releases>

如果你希望开机后自动运行，可以在「设置」中打开「登录时启动」。

## 基本使用

### 按应用手动抓包（实验性）

在「网络监控 → 实时」的应用右侧菜单中选择「抓取当前应用数据包（无需代理）」，会先打开独立抓包窗口。再点击窗口里的「开始抓包」按钮才请求 macOS 管理员授权；授权完成后只有成功创建捕获文件才显示「捕获中」，若失败会显示可复制的错误和重试按钮。DevRadar 使用系统自带的 `tcpdump` 和 `pktap` 按当前应用的 PID 过滤网络包，直接抓取**已运行的原应用**，不会启动新的应用实例。

- 一次只允许一个抓包会话，最长 10 分钟、最多 10,000 个包；每包最多保留 256 字节，临时文件设有大小限制。
- 抓包时使用系统 tcpdump 的实时文本输出，按文件偏移量增量读取摘要，仅保留最近 500 条供界面显示，不再定时重新解码整份捕获文件；累计条数在会话期间持续统计，原始数据仍可导出。
- 菜单栏中显示会话状态，详情位于独立分析窗口。停止后可手动导出 PCAPNG；可随时清除会话。超过一小时的旧会话会在下次启动时清理。
- 原始抓包始终包含 TCP/UDP 443 等常见 HTTPS 端口（不会受旧版 443 过滤设置影响）；**不能解密 HTTPS 请求正文**。
- 对安装在 `/Library/Input Methods/` 和用户输入法目录中的输入法，运行进程即使暂时没有活跃流量也保留在「实时」列表中；原始抓包窗口会显示启动时已经发现的连接目标，但仍只能捕捉**开始以后**传输的数据。微信输入法等直接连接远程 IP、绕过系统 HTTP 代理的应用，应优先使用原始数据包模式。
- PCAPNG 也可能包含明文 HTTP 的请求片段、地址和其他敏感数据，请只在需要诊断时手动启动、审慎导出。
- 当前尚未集成需要正式签名与用户授权的 Network Extension，不能无权限静默抓包，也不能还原抓包开始之前的通信。

### 本机代理抓包及 HTTPS 解密（个人使用）

网络监控的应用菜单还提供「分析系统代理 HTTPS（不限应用）」：

进入「网络监控 → 实时」，点击应用行右侧的 `...`，选择上述一种抓包方式。选择后会自动打开可缩放的独立「DevRadar · 抓包分析」窗口；关闭窗口不会停止抓包，菜单栏中的「查看详情」可以重新打开窗口。历史列表的 `...` 也提供入口，但只有该应用仍在运行时才能抓包。

分析窗口的左侧提供请求搜索、按上传/异常筛选；右侧展示请求方法、域名、路径、状态码、上传/下载字节数及按需启用的正文预览。原始数据包模式提供报文查看与 PCAPNG 导出。抓包窗口可直接停止当前会话。

抓包窗口右侧默认显示「上传诊断概览」，点击某一条请求或原始摘要后进入详情，点击顶部「分析概览」可返回：

- **按 PID 原始抓包**：使用常驻 nettop 监控的应用级速率样本展示近五分钟上传曲线、峰值和突增点（至少四个先前样本，当前上传速率达到 1 MB/s 且超过八个近期样本的中位数四倍；持续高流量不重复计数）。另列出当前非本机 TCP/UDP 连接目标，仅作为**连接快照**；现有系统数据没有逐 IP/域名上传字节数，因此不能将速率曲线错误分配给这些 IP。
- **原应用 HTTPS / QUIC 逐连接统计**：选择「抓取当前应用数据包（无需代理）」后，DevRadar 立刻为已运行的应用 PID 启动非特权 `nettop` 逐连接监控，包含 TCP/UDP 443，并按每条 socket 的 `bytes_out / bytes_in` 累计计数差值显示**监控开始后的上传、下载字节数**，可导出元数据 JSON；不启动新应用、不修改系统代理、不需要 CA 或管理员权限。点击「开始原始 PCAPNG」才额外请求管理员授权抓取原始包。识别为「HTTPS / TLS 443」或「QUIC / UDP 443」是基于端口的推测，不能证明具体应用协议，也不能解密 HTTPS 正文。已经传输的历史字节不纳入监控期计数。没有跟踪到的新进程 PID 和没有走 TCP/UDP 443 的 TLS 流量，也不在该列表中。
- **上传异常自动留存 HTTPS 连接证据**：默认开启，可在设置「异常上传时自动记录 HTTPS 连接证据」关闭。应用上传突增达到 1 MiB/s 且高于近期基线四倍，或持续两次采样超过用户配置的上传速率阈值时，自动针对触发应用的最多 16 个现有 PID 启动一条非特权 `nettop` 连接监控，采样 30 秒；最多同时 2 个应用，同一应用冷却 10 分钟。监控期间的 TCP/UDP 443 逐 socket 上传/下载增量及监测时间自动保存到 `~/Library/Application Support/DevRadar/AutomaticHTTPS/`，目录权限 0700、记录文件 0600，保留最多 7 天或 50 条；网络监控页面「自动 HTTPS 证据 → 查看记录」可查看、导出或删除。清空网络记录也会清理自动证据。**仅记录异常触发后的加密连接元数据，不自动提权抓原始包、不拦截 HTTPS、不读取输入内容或请求正文、不修改系统代理**。触发前的逐连接计数未追溯，没看到 443 连接不代表应用没联网；端口 443 也不等于已确认 HTTPS。
- **统一异常证据时间线 / 报告**：按 PID 抓包窗口的「异常事件时间线」将应用级速率突增和自动 443 连接证据合并查看，自动记录历史窗口也显示相同的展开详情。只在应用 ID 一致、事件 PID 有交集且触发时间相差不超过 12 秒时建立**时间关联**；连续超阈值触发的自动记录没有速率突增时也会独立展示，不会假装匹配。导出完整诊断 JSON v2，分别保留速率样本、时间关联连接快照和监控**开始以后**的 443 逐连接增量，报告注明关联不等于因果、无 HTTPS 解密、不能将应用总流量分摊到某个地址。历史 443 证据可留存 7 天，应用级速率时间线仍仅在内存保留最近 30 分钟（重启后不会伪造补齐）。
- **异常上传事件证据**：从常驻应用流量监控的样本中，在突增时保留前约 16 秒和后约 20 秒的速率、触发时的 PID、及此窗口内实际记录的非本机连接快照（每个快照带独立时间戳，约 6 秒采集一次）。事件最多保留 12 条、30 分钟，只在内存中存在；未进入网络监控页面或未启用连接检查时，可能没有对应的连接快照。点击事件可展开时间线，并手动「导出诊断报告 JSON」，文件权限设为 0600，包含应用名称、PID、速率和快照 IP/端口，**不包含输入内容、HTTP 正文、请求 URL、Headers 或命令行**。导出文件也会明确标注：只能证明突增与连接同时存在，不能证明具体内容、逐 IP 上传量或上传目的。
- **系统 HTTP/HTTPS 代理**：对本次保留的已完成请求按域名累计代理上传字节，展示最大上传请求及 15 秒时间段的上传趋势。来源 PID 尚未识别，因此它们**不能**代表从菜单选择的应用上传的数据。统计不包含绕过代理的直连、正在执行的请求和透明升级连接中的所有流量；会话最多保留最近 2000 条记录。图表和排行不从完整设备流量倒推或虚构归属。

HTTP/HTTPS 代理请求现在显示进行中、完成或失败状态，并记录 UTC 时间和耗时（毫秒），同一个请求的开始与结束使用相同 ID 合并显示。界面最多保留最近 2000 条事件。点击「导出会话 JSON」可保存最近的**元数据记录**：域名、方法、状态、耗时和上传/下载字节数；出于隐私保护，导出文件**不包含路径、查询参数、请求正文、响应正文或 Headers**，且明确标注系统代理请求的来源进程未经验证。导出文件由用户手动选择位置，文件权限为 0600。

正文中包含 JSON 时，详情面板自动切换为可折叠的 JSON 树，提供逐级展开/折叠、全部展开/折叠和「格式化文本」视图。支持单个 JSON、NDJSON（按行分隔）及多个直接相连的 JSON 对象。预览若因长度限制截断，会显示已成功解析的完整对象，并保留未完成的尾部片段；非 JSON 正文保持原文本显示。复制按钮仅复制当前已经脱敏、受到抓包长度限制的预览内容。

实时应用列表默认锁定应用行的位置，上传和下载数值仍持续更新；点击顶部「上传」或「下载」时才按照最新值重新排序，防止列表在点击应用 `...` 时跳动。

**不再启动新的 Chrome 或其他应用实例。**如果仅需看原有 Chrome 的连接、IP、端口和原始包，直接使用按 PID 原始抓包。要在已运行 Chrome 中查看 HTTPS 请求内容，先启动本地代理，再在分析窗口点击「让现有应用走代理（会影响系统网络）」，阅读确认框并主动确认。DevRadar 才会临时修改默认网络服务的 HTTP/HTTPS 代理设置，让支持系统代理的原有应用发送新请求时经过 DevRadar。HTTP/HTTPS 代理配置需要 macOS 管理员授权，无法只针对选中一个 PID。

**请求归属警告**：当前 Go 代理引擎没有可验证的来源 PID，HTTPS 列表统一标为「来源未识别 · 系统代理」，不能因为从某个应用的菜单进入就把请求归因到该应用。只有系统级请求列表，不提供虚假的单应用 HTTPS 上传统计；需要确认单应用连接信息时使用按 PID 原始数据包模式。标准 HTTP/1.1 WebSocket Upgrade 支持透明双向转发，但不读取其中的消息内容；HTTP/2 / HTTP/3 的完整中间人支持仍不包含在当前版本内。

1. 如需查看 HTTPS 请求，在「设置 → 本地代理 · 个人使用」开启「代理 HTTPS 解密」；需要查看正文时再打开「记录脱敏正文预览」，默认不记录正文。
2. 点击「生成 / 定位 CA 证书（.cer）」，打开「钥匙串访问」，**选中「登录（login）」钥匙串**，再拖入 `.cer` 公共证书。不要导入 `.key` 私钥。如仍无法导入，使用「复制终端导入命令（备用）」。导入后在证书的「信任」设置中按需开启 SSL 信任，或使用「复制仅 SSL 信任命令（备用）」并亲自确认 macOS 授权。
3. 在原应用分析窗口中选择「让现有应用走代理（会影响系统网络）」并确认。系统原来的 HTTP/HTTPS 代理会先保存到用户目录的恢复文件，DevRadar 作为第一跳，并继续将请求转发给原代理。当前 Wi-Fi 使用的 127.0.0.1:7890 等代理不会被无条件丢弃。若现有代理不兼容、使用 PAC 或已发生变更，DevRadar 会拒绝自动切换。
4. 继续在原来的应用中发起新请求。分析窗口显示经由临时代理的请求。完成后点击「停止抓包」，**确认系统代理恢复成功**，再退出 DevRadar。若异常退出，在菜单栏点击「系统代理待恢复 → 恢复」。

本地引擎用 Go 标准库编写并随 App 打包，运行时不需要 Go 或 mitmproxy，不需要 Developer ID 或 Network Extension。**不会未经明确确认修改系统代理；用户主动开启临时代理模式后会影响所有遵循该系统网络配置的应用。**

注意：
- **无法按单个 PID 透明解密 HTTPS。**用户授权的临时系统代理模式可以让部分已经运行的应用改道，但不是单应用隔离：选择应用只用于会话名称，其他使用相同代理端口的应用也可能被捕获。证书固定、自定义协议、手工覆盖代理或不遵循系统代理的应用可能无法解密。
- 为确保代理变更可恢复，切换前会备份现有 HTTP/HTTPS 配置到本机，切换和恢复后均重新读取验证结果，校验通过才删除恢复记录。若管理员拒绝恢复、应用强制退出或电脑断电，网络可能暂时不可用。需要重启 DevRadar 并使用「恢复系统代理」，恢复成功前不要删除备份文件。SOCKS、PAC、代理例外域名不由 DevRadar 修改。
- 本机 CA 的私钥保存在 ~/Library/Application Support/DevRadar/CaptureCA/，请勿复制或上传。仅将公开的 PEM 证书加入受信任证书列表。
- 请求正文预览最多 2 KB，自动脱敏并不保证识别所有敏感字段；不要把真实凭据当作测试数据。
- 排查完成后建议从登录钥匙串撤销 DevRadar Local Capture CA 信任。
- `.cer` 和 `.pem` 是同一张 CA 的不同编码，不会重新生成证书或更换私钥。

点击菜单栏中的 DevRadar 图标，可通过底部导航切换「项目」「端口」「网络」三个页面。项目管理见上方说明，端口和网络功能如下：

### 端口监控

默认只显示开发服务。你可以搜索项目、端口、PID 或命令，也可以切换为显示所有监听端口。

项目列表支持按名称、CPU、内存和运行时长排序。

### 网络监控

可以在「实时 / 1 天 / 3 天 / 7 天」之间切换。

点击网络监控标题旁的「DNS」打开只读诊断窗口：

- 显示 macOS 当前默认、分域及接口限定 DNS 解析器；支持手动刷新。
- 输入域名进行系统正向解析（IPv4 / IPv6），输入 IP 进行反向名称查询；显示结果与耗时。
- 域名解析 IP 与当前应用远程连接一致时，展示对应应用作为辅助线索；展开应用的「远程连接」可点击地球图标反查该 IP。
- 不接管或更改系统 DNS，不要求管理员权限，不监控其他应用的完整 DNS 查询历史。系统解析可能使用缓存、hosts、mDNS 或 VPN；IP 匹配与反向 DNS 名称都**不能证明域名由某应用访问**。
- DNS 窗口的「开始监听」可以手动授权一次性采集本机明文 53 端口查询，按 DNS 请求/响应匹配展示域名、查询类型、返回 IP、时间和可用时的 PKTAP PID。最长 5 分钟，最多 6000 个数据包，仅在内存保留最近 400 条查询，停止并清空后可删除临时记录。不自动安装或常驻 DNS 捕获服务，监听需要 macOS 管理员权限。
- 只有能从 DNS 报文中匹配到返回 IP，且 PKTAP 报文元数据明确带有 PID，才会提示对应应用的连接关联；如恰好发生上传异常，会提示同一时间段。**仅为证据线索，不证明上传目标或 HTTPS 请求域名**。DoH、DoT、QUIC 加密 DNS、查询缓存和未经过本机抓包接口的流量无法被此功能看到。

点击顶部的「上传」或「下载」即可按对应流量排序；再次点击会切换升序和降序。

历史流量只保存在本机。如果不想保留，可以进入：

`设置 → 网络监控 → 清空网络记录`

## 隐私

DevRadar 的监控和统计都在本机完成。

- 不需要登录账号
- 不会把扫描结果上传到 DevRadar 的服务器
- 网络历史记录保存在 `~/Library/Application Support/DevRadar/`
- 只读取进程、端口、网络连接和与项目识别有关的本机信息

常驻网络监控默认不解密 HTTPS。只有你手动开启本地代理解密、为目标应用配置代理并信任 CA 时，才会处理解密的 HTTP 请求；捕获事件只暂存在 App 内存里。

## 常见问题

### 为什么有些进程只显示 `node` 或 `python`？

DevRadar 会优先使用工作目录、完整启动命令和父进程链来识别项目。如果这些信息已经被系统回收，或者进程本身没有携带项目路径，就只能显示运行时名称。

### 为什么应用的流量和代理软件中的统计不完全一致？

DevRadar 按本机进程统计网络活动。代理转发、本机回环连接、系统辅助进程等情况可能造成统计口径不同，因此它更适合用来判断「哪个应用在产生流量」，而不是作为运营商级别的流量计费工具。

### 网络历史会一直增长吗？

不会。DevRadar 只保留用于 1 天、3 天和 7 天统计所需的短期数据，并会自动清理更早的记录。
